# دامنهٔ آزمایش‌ها

## آزمایش زندهٔ نمونهٔ اولیه — ۱۰ اکتبر ۲۰۲۶

نسخهٔ پیش از نام‌گذاری عمومی، با همان موتورهای NaiveProxy، Xray و Caddy روی دو سرور متعلق به توسعه‌دهنده بررسی شد: ایران Ubuntu 22.04 با 3x-ui 3.8.5، و خارج Ubuntu 26.04 با گواهی عمومی معتبر.

- دانلود ۶۴ کیلوبایت و ۱۶ مگابایت، آپلود ۴ مگابایت و تطبیق هش، در هر دو مسیر Naive و XHTTP موفق بود. ۱۶ اتصال با هم‌زمانی ۴ نیز بررسی شد.
- DNS از UDP به دو resolver عبور کرد. ترافیک کاربر آزمایشی در پنل ایران ثبت شد.
- خرابی Naive به XHTTP، خرابی نود اول به نود دوم و بازگشت مسیر بررسی شد. توقف همهٔ مسیرها به خروج مستقیم ایران منجر نشد.
- درخواست بدون اعتبارنامه، گواهی با نام اشتباه و اعتبارنامهٔ اشتباه رد شدند.
- در ۲۱ نمونهٔ سلامت طی حدود ۱۰ دقیقه، هر چهار بررسی Naive، XHTTP، TCP خودکار و UDP موفق بودند.

دو نود آزمایشی روی **یک سرور فیزیکی خارج** بودند؛ این آزمون، استقلال دیتاسنتر یا تحمل خرابی چند اپراتور را ثابت نمی‌کند. آزمون ده‌دقیقه‌ای، آزمون بار سنگین یا پایداری چندروزه نیست. پاسارگارد و CDN در این آزمایش زنده بررسی نشدند. IP، دامنه، اعتبارنامه‌ها و خروجی خام خصوصی این آزمایش در مخزن عمومی قرار نمی‌گیرند.

## بررسی نسخهٔ عمومی

برای v0.1.4، هر ۶۳ آزمون روی هر دو سرور Linux ایران و خارج موفق بود. بررسی‌ها شامل پورت‌های پیش‌فرض اشغال، تداخل UDP، حفظ پورت نصب‌های قبلی، افزودن/حذف/جایگزینی نود، بازگردانی تنظیمات پس از خطای سرویس، ورودی قابل‌نمایش کد اتصال و یکسان‌بودن پورت‌ها در خروجی پنل، مسیریاب و کنترل سلامت است.

در آزمون زندهٔ جداگانه روی میزبان خارج، پنج پورت پیش‌فرض واقعاً اشغال شدند و دو نود منطقی با پورت‌های جایگزین اجرا شدند. هر شش بررسی Naive، XHTTP و UDP موفق بود؛ کنترل‌گر از API روی پورت جدید استفاده کرد و TCP/UDP از خروجی خودکار و خروجی هر دو نود عبور کرد. شناسه و وضعیت سرویس‌های موجود تغییر نکردند و فرایندهای آزمایشی پس از پایان پاک‌سازی شدند. دو نود به یک سرور خارج متصل بودند؛ این آزمون استقلال چند دیتاسنتر را اثبات نمی‌کند.

روی ایران نیز انتخاب پورت‌های جایگزین و اجرای موتورهای آزمایشی موفق بود، اما اتصال زنده به نود خارج در این نوبت موفق نشد: اتصال مستقیم TLS از ایران reset می‌شد، در حالی که HTTPS نود از خود میزبان خارج پاسخ معتبر می‌داد. بنابراین نتیجهٔ آزمون فوق، تأیید سالم‌بودن مسیر فعلی ایران یا مقاومت در برابر فیلترینگ نیست.

برای v0.1.3، هر ۵۱ آزمون روی سرور Linux خارج موفق بود و تنظیمات تولیدی نیز با موتورهای واقعی بسته اعتبارسنجی شدند. صدور و تمدید واقعی گواهی با افزونهٔ Nginx در محیط آزمایشی Let’s Encrypt و با پوشه‌های جداگانه انجام شد؛ گواهی عمومی موجود جایگزین نشد. در ۱۰۶ بررسی HTTP پیوسته، پاسخ وب‌سرور با پاسخ مبنا یکسان بود؛ شناسهٔ فرایند اصلی Nginx و محتوای فایل‌های تنظیمات آن نیز تغییر نکردند. این بررسی شامل خاموش‌کردن یا راه‌اندازی مجدد Nginx نبود.

بارگذاری گواهی جدید با همان Caddy موجود در بسته، هنگام دانلود پیوسته آزمایش شد: اتصال جدید گواهی تازه را دریافت کرد، دانلود قبلی با اندازه و هش صحیح تمام شد و فرایند Caddy عوض نشد. آزمون‌های خودکار همچنین انتخاب روش صدور، جلوگیری از اجرای hookهای توقف سفارشی هنگام مهاجرت، انتخاب زمان‌بند تمدید و اجرا نشدن hook برای نود خاموش یا گواهی نامرتبط را پوشش می‌دهند. آزمون زندهٔ ACME روی Nginx میزبان و Certbot نسخهٔ 5.8.0 انجام شد؛ مسیر سازگاری نسخه‌های قدیمی‌تر با آزمون شبیه‌سازی‌شده بررسی شده است.

برای v0.1.2، هر ۳۲ آزمون روی سرور Linux خارج موفق بود؛ بررسی‌ها شامل انتخاب IP، پورت اشغال در IPv4/IPv6، انتخاب پورت داخلی جایگزین، گواهی و کلید واقعی، نام دامنهٔ اشتباه، گواهی نزدیک انقضا و اصلاح ورودی نامعتبر در منو هستند. پیشنهادهای منو نیز روی همان سرور با پورت‌های اشغال و گواهی موجود بررسی شدند؛ در این بررسی، مرحلهٔ ساخت نود اجرا نشد و سرویس‌های زنده تغییری نکردند. این آزمون‌ها مربوط به نصب و رابط مدیریت‌اند، نه ارزیابی تازهٔ مقاومت در برابر فیلترینگ.

برای آماده‌سازی v0.1.0، هر ۱۳ آزمون روی رایانهٔ توسعه و هر دو سرور Linux موفق بود. نصب بسته و نصب مجدد با همان موتورهای انتقال روی هر دو سرور بررسی شد؛ در سرور خارج نصب خودکار وابستگی‌های گمشده نیز موفق بود. تنظیمات ایران، خارج، خروجی پنل/DNS و دو حالت Caddy با خود موتورهای بسته اعتبارسنجی شدند.

از ایران، موتورهای بستهٔ عمومی روی پورت‌های loopback جدا اجرا شدند و TCP از Naive و XHTTP، UDP و انتخاب هر دو مسیر TCP با API مسیریاب موفق بود. نود خارجِ موجود مقصد این آزمون بود؛ تنظیمات کاربران و مسیر زندهٔ قبلی برای این آزمون جابه‌جا نشد. این بررسی جای آزمون چندروزه یا نصب واقعی پاسارگارد را نمی‌گیرد.

آزمون‌های سورس:

```bash
python3 -m unittest discover -s tests -v
for script in install.sh install-local.sh build-bundle.sh; do bash -n "$script"; done
```

تست‌ها اعتبارسنجی کد اتصال، انتخاب مسیر TCP/UDP، قطع خروجی هنگام خرابی، ثبات پورت، محدودیت listenerها و بسته‌بندی بدون فایل خصوصی را پوشش می‌دهند. گردش‌کار GitHub این بررسی‌ها را روی Linux اجرا می‌کند. ساخت موتورهای نسخهٔ ثابت و بررسی تنظیمات تولیدی در گردش‌کار جداگانهٔ Build قابل‌اجراست.

آزمون موفق نصب یا TLS به‌تنهایی اثبات مقاومت در برابر فیلترینگ نیست. برای ارزیابی واقعی، یک ورودی محدود روی اپراتورهای کاربران و برای مدت طولانی‌تر آزمایش کنید.
