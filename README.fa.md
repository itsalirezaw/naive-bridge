# NaiveBridge — راهنمای فارسی

**تانل بین سرورها بر پایهٔ NaiveProxy و پشتهٔ شبکهٔ Chromium.** کاربران به سرور ایران متصل می‌شوند؛ پنل ایران احراز هویت، حجم و انقضا را مدیریت می‌کند و ترافیک منتخب از طریق نود خارج به اینترنت می‌رسد.

مسیر اصلی TCP، **Naive روی HTTPS/HTTP2** است. XHTTP با TLS معتبر، مسیر پشتیبان TCP و حامل UDP است؛ خود Naive در این پروژه UDP حمل نمی‌کند. این نسخه اتصال مستقیم دارد و به Cloudflare CDN یا REALITY نیاز ندارد.

نسخهٔ **۰٫۱٫۴ آزمایشی** است. نام NaiveBridge مربوط به ابزار نصب و اتصال این اجزاست؛ هستهٔ NaiveProxy ساختهٔ این پروژه نیست. استفاده از پشتهٔ Chromium و سازوکارهای Naive به کاهش برخی نشانه‌های ترافیک کمک می‌کند، اما تضمین غیرقابل‌شناسایی بودن نمی‌دهد. [منبع NaiveProxy](https://github.com/klzgrad/naiveproxy) · [محدودهٔ آزمایش‌ها](docs/testing.fa.md)

## پیش‌نیازها

- سرور ایران با پنل Xray مانند 3x-ui؛ نصب مستقیم روی میزبان، یا Docker با شبکهٔ host.
- یک یا چند سرور خارج. نیازی به نصب پنل و ساخت کاربران روی خارج نیست.
- Linux با معماری x86_64، systemd و دسترسی root. موتورهای این نسخه ARM64 نیستند.
- روی Ubuntu/Debian، وابستگی‌های اجرایی هنگام نصب دریافت می‌شوند. Python باید 3.10 یا جدیدتر باشد. آزمون زندهٔ نمونه روی Ubuntu 22.04 و 26.04 انجام شده است.
- برای هر نود خارج، یک دامنه یا زیردامنه که مستقیم به IP آن اشاره کند. اگر DNS روی Cloudflare است، **ابر نارنجی خاموش / DNS only** باشد.
- یک پورت آزاد TCP روی خارج، ترجیحاً ۴۴۳. برای صدور و تمدید خودکار گواهی، پورت ۸۰ باید از اینترنت قابل‌دسترسی باشد؛ اگر Nginx روی میزبان فعال است از خود آن استفاده می‌شود، وگرنه پورت ۸۰ باید آزاد باشد. فایروال سرور و ارائه‌دهنده باید این پورت‌ها را مجاز کنند؛ نصب‌کننده قوانین فایروال را تغییر نمی‌دهد.

مثال‌ها از `node.example.com` و `203.0.113.5` استفاده می‌کنند؛ آن‌ها را با دامنه و IP خود جایگزین کنید. اگر رکورد AAAA دارید، باید به IPv6 صحیح همین نود اشاره کند.

## ۱. نصب روی خارج

ابتدا رکورد دامنه را ایجاد کنید، سپس با root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/itsalirezaw/naive-bridge/main/install.sh)
```

اگر curl نصب نیست:

```bash
apt-get update && apt-get install -y curl ca-certificates
```

نصب‌کننده بستهٔ آماده و checksum را از انتشار رسمی دریافت می‌کند، فایل‌ها را بررسی می‌کند و منوی انگلیسی را باز می‌کند. تمام پیام‌ها و پرسش‌های اسکریپت انگلیسی‌اند؛ این راهنما فارسی است. برای بازکردن دوبارهٔ منو، `naive-bridge` را اجرا کنید.

گزینهٔ **1 — Set up an outside node** برای راه‌اندازی نود خارج:

1. نام نود: مثلاً `fi1`. نام باید با حرف کوچک شروع شود و حداکثر ۱۶ حرف کوچک یا عدد باشد.
2. IP عمومی خارج: اسکریپت IP را تشخیص می‌دهد و در کروشه پیشنهاد می‌کند. اگر درست است Enter بزنید؛ در غیر این صورت IP صحیح را وارد کنید. اگر تشخیص ممکن نبود، ورود دستی لازم است.
3. دامنه: زیردامنه‌ای که در مرحلهٔ قبل ایجاد کردید.
4. پورت HTTPS: اسکریپت از `443` شروع می‌کند و در صورت اشغال، `8443`، `9443`، `10443` و سپس پورت‌های بعدی را بررسی می‌کند. Enter پورت آزاد پیشنهادی را می‌پذیرد؛ امکان ورود دستی هم هست. آزادبودن فقط روی خود سرور بررسی می‌شود؛ پورت انتخابی باید در فایروال سرور و ارائه‌دهنده مجاز باشد. پورت داخلی XHTTP از بازهٔ `20300–20399` خودکار انتخاب می‌شود و نباید عمومی باز شود.
5. گواهی: اگر گواهی موجود و منطبق با دامنه در `/etc/letsencrypt/live` پیدا شود، مسیر `fullchain.pem` و کلید آن پیشنهاد می‌شود؛ برای تأیید هرکدام Enter بزنید. در غیر این صورت Enter گزینهٔ `auto` را انتخاب می‌کند: Nginx فعالِ میزبان با افزونهٔ رسمی Certbot و بدون توقف سرویس گواهی می‌گیرد؛ در نبود Nginx از پورت آزاد ۸۰ استفاده می‌شود. پورت ۸۰ در هر دو حالت باید از اینترنت قابل‌دسترسی باشد. مسیر گواهی تازه خودکار انتخاب می‌شود و تمدید نیز زمان‌بندی می‌شود. برای استفاده از گواهی دیگر، مسیر کامل فایل را وارد کنید؛ عدد `80` یا پوشه‌ای مثل `/root` مسیر فایل گواهی نیست. فایل‌ها باید برای سرویس قابل‌خواندن باشند؛ مسیرهای `/etc` مناسب‌اند. ورودی نامعتبر همان‌جا دوباره پرسیده می‌شود.

نام دامنه را خودتان وارد می‌کنید. IP پیشنهادی به‌خصوص روی سرورهای چند IP یا پشت NAT نیازمند بررسی شماست. اسکریپت برای آزادکردن پورت، سرویس قبلی را متوقف نمی‌کند. برای نمایش منوی به‌روز پس از نصب مجدد، از منوی قبلی با `0` خارج شوید و `naive-bridge` را دوباره اجرا کنید.

پس از موفقیت، پیام برجستهٔ `SUCCESS - OUTSIDE NODE SETUP COMPLETE` اعلام می‌کند که کار روی خارج تمام شده و باید به ایران بروید. **کد محرمانه با پیشوند `NB1.`** بین دو خط BEGIN و END نمایش داده می‌شود؛ فقط کل خط کد را کپی کنید، بدون عنوان‌ها. منو تا زدن Enter صبر می‌کند. این کد شامل اطلاعات دسترسی نود است؛ آن را در ویدیو، issue یا تصویر عمومی نشان ندهید. گزینهٔ **7 — Show outside node pairing code** دوباره کد را نمایش می‌دهد. برای دریافت کد خام با فرمان:

```bash
naive-bridge export fi1
```

## ۲. نصب روی ایران

همان دستور نصب را روی ایران اجرا کنید؛ سپس گزینهٔ **2 — Add a node on Iran** را انتخاب و کل کد را بچسبانید و Enter بزنید. **متن کد هنگام ورود دیده می‌شود.** پس از پذیرفته‌شدن، نام نود و دامنه/پورت خارج نمایش داده می‌شود. ورودی نامعتبر همان‌جا دوباره پرسیده می‌شود.

پورت‌های محلی ایران خودکار انتخاب و ذخیره می‌شوند. اگر `20080` یا پورت داخلی دیگری اشغال باشد، پورت آزاد جایگزین انتخاب می‌شود؛ سرویس قبلی متوقف نمی‌شود. این پورت‌ها **لازم نیست با پورت خارج یکی باشند** و نباید روی اینترنت باز شوند. پورت خارج از خود کد اتصال خوانده می‌شود. پورت‌های نودهای موجود هنگام افزودن یا حذف نود دیگر ثابت می‌مانند.

پیام `SUCCESS - IRAN NODE SETUP COMPLETE` یعنی نود ذخیره شده و سرویس‌های محلی اجرا شده‌اند. این پیام پورت واقعی اتصال پنل و مرحلهٔ بعد را نشان می‌دهد؛ هنوز به معنی تأیید اتصال سرتاسری یا تکمیل تنظیمات پنل نیست. حدود ۲۰ ثانیه برای بررسی اولیه صبر کنید و گزینهٔ **6** را بزنید، یا اجرا کنید:

```bash
naive-bridge status
naive-bridge doctor
```

در `doctor` سه بررسی `naive`، `xhttp` و `udp` باید موفق باشند. `ok: true` فقط نتیجهٔ همین بررسی است؛ تضمین پایداری بلندمدت نیست. `stale: true` در وضعیت یعنی نتیجهٔ ذخیره‌شده تازه نیست.

## ۳. اتصال به پنل ایران

```bash
naive-bridge panel
```

خروجی، تنظیمات آمادهٔ SOCKS برای پنل با **پورت‌های واقعی همین نصب** است؛ آن را از گزینهٔ **4** هم می‌توانید بگیرید. پورت را `20080` فرض نکنید. خروجی‌ها را به **Outbounds** پنل اضافه کنید و ورودی آزمایشی را با یک قانون **Routing** به `naive-bridge-auto` متصل کنید. تنظیمات کامل پنل را با این قطعه جایگزین نکنید.

**[راهنمای گام‌به‌گام 3x-ui، پاسارگارد، JSON و DNS](docs/panels.fa.md)**

افزودن outbound به‌تنهایی مسیر کاربران را عوض نمی‌کند. کاربران همچنان به IP یا دامنهٔ سرور ایران متصل می‌شوند و حسابداری روی همان پنل انجام می‌شود.

## افزودن نودهای بیشتر

روی سرور خارج بعدی همین نصب را انجام دهید و نام متفاوتی مانند `de1` انتخاب کنید. کد آن را در منوی ایران اضافه کنید. سقف پیکربندی این نسخه ۳۲ نود است؛ برای ظرفیت کاربران بنچمارک عمومی انجام نشده است.

`naive-bridge-auto` با ترتیب ثبت نودها، مسیر سالم را انتخاب می‌کند. خروجی `naive-bridge-fi1` به نود مشخص محدود است. خروجی‌های جدید را با `naive-bridge panel` بگیرید و به پنل اضافه کنید. تقسیم کاربران بین نودها با قوانین پنل انجام می‌شود؛ تقسیم بار وزنی خودکار در این نسخه وجود ندارد.

## نصب آفلاین

اگر GitHub از ایران در دسترس نیست، دو فایل زیر را از [صفحهٔ انتشار](https://github.com/itsalirezaw/naive-bridge/releases) روی رایانه یا خارج دانلود و با SFTP به هر دو سرور منتقل کنید:

- `naive-bridge-linux-amd64.tar.gz`
- `SHA256SUMS`

در پوشهٔ همان دو فایل اجرا کنید:

```bash
sha256sum -c SHA256SUMS
tar -xzf naive-bridge-linux-amd64.tar.gz
cd naive-bridge
bash install-local.sh
```

بسته هر سه موتور را دارد؛ برای نصب آن دانلود موتور از GitHub لازم نیست. دریافت وابستگی‌های توزیع و صدور گواهی خودکار همچنان ممکن است به شبکه نیاز داشته باشد. checksum سلامت فایل را بررسی می‌کند؛ فایل و checksum را از منبع معتبر دریافت کنید.

## رفتار هنگام اختلال

TCP ابتدا Naive نود اول، سپس XHTTP همان نود و سپس نود بعدی را انتخاب می‌کند. UDP فقط از مسیر XHTTP سالم عبور می‌کند. دو موفقیت متوالی، مسیر را سالم و دو شکست متوالی، آن را خراب اعلام می‌کنند؛ زمان تشخیص به timeout و تعداد نودها وابسته است.

تعویض مسیر برای اتصال‌های **جدید** است؛ دانلود یا اتصال TCP قبلی به نود بعدی منتقل نمی‌شود. اگر همهٔ مسیرها خراب باشند، ترافیک انتخاب‌شده مسدود می‌شود و از ایران مستقیم خارج نمی‌شود. قوانین دیگر پنل مستقل‌اند.

افزودن، حذف یا جایگزینی نود، مسیریاب ایران را restart می‌کند و ممکن است اتصال‌های فعال را قطع کند. بررسی TCP فعلاً به دریافت دادهٔ معتبر از خود نود و یک مقصد خارجی وابسته است؛ اختلال آن مقصد هم می‌تواند خطای سلامت ایجاد کند.

## مدیریت و رفع اشکال

```bash
naive-bridge
naive-bridge status
naive-bridge doctor
naive-bridge restart
naive-bridge stop
naive-bridge start
journalctl -u naive-bridge-watch -u naive-bridge-router -n 40 --no-pager
```

تنظیمات در `/etc/naive-bridge`، وضعیت در `/var/lib/naive-bridge` و موتورهای انتقال در `/opt/naive-bridge` قرار دارند. SOCKS و API فقط روی loopback گوش می‌دهند. قبل از ارسال log، نام دامنه، IP و اطلاعات دسترسی را حذف کنید.
